# 김치사이트 함정 모음 (2026-11 조사)

SKILL.md는 규칙만 담는다. 이 파일은 그 규칙의 근거로, 함정마다 증상 · 대처 · 하면 안 되는 것 · 출처를 적는다.
2026년 11월에 실제로 겪은 것과, 웹 · 공개 페이지를 따로 조사한 것을 모았다. 숫자 · 판 번호 · 판결은 원문을 다시 열어 대조했다(대조하지 못한 것은 맨 끝 「확인 못 한 것」에 있다).

근거 딱지:
- 「확인」 = 1차 출처 본문을 읽었거나 실제 페이지에서 직접 봤다. 1차 출처는 공식 문서, 그 제품 · 서비스를 만든 곳이 쓴 글, 실물을 직접 뜯어본 분석이다.
- 「문서」 = 남이 쓴 2차 안내(다른 업체 도움말 · 판결 요지 사이트 · 다른 기관 답변).
- 「감」 = 보도 · 블로그 · 포럼 · 검색 요약이거나 원리로 짐작했다. 시험해 보지 않았다.

항목 머리 기호: ❗ 사고가 크게 날 수 있음 · ⚠️ 자주 걸리거나 헷갈림 · ℹ️ 참고.

정책 · 판 번호 · 운영 시간은 해마다 바뀐다. 「이 사이트는 보안 프로그램이 필요하다 · 없다」를 이 파일만 보고 단정하지 말고, 그날 화면으로 말한다.

## 가. 보안 프로그램 · 인증

**가1 ❗ 보안 프로그램 설치 화면이 되풀이됨 — 크롬 로컬 네트워크 권한(LNA)**
- 증상: 프로그램을 이미 깔았는데 설치 안내 화면으로 계속 돌아간다. 주소창 근처에 「로컬 네트워크의 기기를 찾고 연결」 같은 권한 창이 뜬다.
- 까닭: 보안 프로그램(Veraport · IPinside · nxKey 등)은 PC 안(127.0.0.1)에 작은 서버를 띄우고, 사이트 JS가 거기에 말을 건다. 크롬 142부터는 공개 사이트가 127.0.0.1이나 사설 IP로 요청하려면 사용자 허락을 받아야 한다. 엣지는 143부터 같다.
- 대처: 다시 깔라고 권하기 전에 이 권한부터 의심한다. 권한 창은 웹 페이지 밖의 브라우저 화면이라 DOM에 안 보이고, 확장의 스크린샷에도 주소창 · 권한 풍선이 안 찍힐 수 있다(감 — 시험 안 함). 「안 보인다」를 「없다」로 읽지 말고 사용자에게 주소창 근처를 봐 달라고 한다. 사용자에게 「주소창 왼쪽 사이트 정보 → 로컬 네트워크 액세스 허용 → 새로고침」을 안내한다.
- 하면 안 됨: 권한 창을 에이전트가 누르기. `chrome://flags/#local-network-access-check` 끄기(보안 설정이라 사람이 직접 판단). 페이지 JS로 127.0.0.1 포트를 찔러 보기.
- 출처: https://developer.chrome.com/blog/local-network-access (확인 — 「launching in Chrome 142」 · 플래그 이름) · 하나은행 FAQ https://biz.kebhana.com/cont/customer/customer04/customer047/customer0478/index.jsp (확인 — 크롬 142 · 엣지 143 · 「설치 페이지가 반복적으로 표시」 · 해결 순서. 이 FAQ는 2단계로 flags에서 검사를 끄는 것도 안내하는데, 보안 설정이라 사람이 판단할 일이다 — 에이전트가 먼저 권하지 않는다) · 크롬 145에서 권한이 「로컬 네트워크」와 「기기에 있는 앱」 두 칸으로 갈라졌다는 말은 블로그 하나뿐이다(감 — 크롬 블로그에는 없음).

**가2 ❗ 보안 프로그램은 브라우저 밖에 산다**
- 증상: 「통합설치」를 누르면 윈도 창(예: Wizvera updater)이 뜬다. 이 창은 탭 · DOM · 확장 스크린샷 어디에도 안 잡힌다. 서명 오류가 나면 「계속」 상자가 뜬다.
- 까닭: Veraport는 관리자 권한으로 돌면서, 사이트가 보낸 목록대로 여러 프로그램을 연달아 설치한다.
- 대처: 설치 단추가 보이면 멈춘다. 페이지에 적힌 프로그램 이름을 그대로 사용자에게 알린다. 「에이전트 눈에 안 보인다」를 「안 떴다」로 읽지 말고 사용자에게 화면을 묻는다.
- 하면 안 됨: 설치 단추 · 서명 오류의 「계속」 누르기(내려받기 · 실행).
- 출처: https://palant.info/2023/03/06/veraport-inside-koreas-dysfunctional-application-management/ (확인 — 보안 연구자의 2023년 실물 분석)

**가3 ❗ IPinside 응답이 없으면 로그인 자체가 막힘**
- 증상: 로그인 단추를 누르면 「설치 필요」로 튕긴다. 크롬에서는 설치 창이 되풀이되거나 다시 켠 뒤 재설치를 요구하기도 한다.
- 까닭: 사이트 JS가 localhost의 IPinside에 요청하고, 실패하면 들여보내지 않는다. 크롬 네트워크 샌드박스 · 꺼진 시작 프로그램 · VPN 가상 어댑터도 같은 증상을 낸다.
- 대처: 보안 프로그램이 안 붙는 Claude 앱 안 브라우저에서는 여기서 막힐 것으로 보인다(감). 로그인 화면까지만 가고 사람에게 넘긴다. 증상 이름과 은행 FAQ 주소를 함께 건넨다.
- 하면 안 됨: 응답 흉내 내기 · 다시 보내기. 실행 옵션 · 시작 프로그램 · 네트워크 어댑터를 에이전트가 바꾸기(시스템 설정).
- 출처: https://palant.info/2023/01/25/ipinside-koreas-mandatory-spyware/ (확인 — 실물 분석) · https://biz.kebhana.com/cont/customer/customer04/customer047/customer0471/index.jsp (확인 — 은행 자체 안내)

**가4 ❗ 키보드 보안 칸에는 넣은 값이 안 들어감**
- 증상: 비밀번호 칸에 보이는 글자가 친 것과 다르거나 비어 있다. 로그인하면 「비밀번호 오류」가 난다.
- 까닭: TouchEn nxKey 같은 키보드 보안은 커널 드라이버로 키를 가로채 암호화한다. 암호문은 숨은 칸에 넣고, 눈에 보이는 칸에는 가짜 글자만 준다. 서버는 숨은 칸만 믿는다. 그래서 JS로 value를 넣으면 숨은 칸이 빌 것으로 보인다(감 — 구조로 짐작).
- 대처: 칸 옆에 「키보드 보안」 표시가 있으면 그 칸은 사람 몫이다. 비밀번호 · 인증서 비밀번호 칸에는 애초에 값을 넣지 않는다. 비밀번호가 아닌 칸(검색어 · 날짜 등)에도 걸려 있을 수 있으니, 그런 칸에 한해 값을 넣은 뒤 JS로 다시 읽어 대조하고, 다르면 멈춘다.
- 하면 안 됨: 키보드 보안 끄기 토글 누르기. 같은 칸에 여러 번 다시 치기(틀린 횟수가 쌓여 계정이 잠길 수 있다).
- 출처: https://palant.info/2023/01/09/touchen-nxkey-the-keylogging-anti-keylogger-solution/ (확인 — 「The actual password field receives only dummy text.」)

**가5 ❗ 가상 키패드 · 마우스 입력기**
- 증상: 비밀번호 칸을 누르면 그림 자판이 뜨고, 누를 때마다 배열이 바뀐다. DOM에는 글자가 없다.
- 대처: 바로 사용자에게 맡긴다(「화면 자판이 떴어요. 직접 눌러 주세요」).
- 하면 안 됨: 스크린샷으로 자판을 읽고 좌표를 누르기 — 비밀번호 입력이자 우회다.
- 출처: 보안 업체 제품 안내(감 — 검색 요약으로만 봄)

**가6 ⚠️ 「개발자도구 · 디버그 도구를 탐지하였습니다」**
- 증상: 금융 · 보험 사이트에서 이 창이 되풀이해 뜨고 페이지가 계속 새로고침된다. `javascript_tool`이 멈추거나 시간 초과가 난다.
- 까닭: 보안 프로그램이 탐지하거나, 사이트가 `debugger` 무한 되풀이를 심어 둔 경우다. 확장의 디버거 연결이 탐지에 걸리는지는 확인 못 했다.
- 대처: 같은 방법을 다시 하지 않는다. 막힘 규칙대로 방법을 바꾸거나 사람에게 넘긴다.
- 하면 안 됨: debugger 우회 스크립트 넣기. 보안 프로그램을 지우라고 먼저 권하기.
- 출처: https://palant.info/2023/01/02/south-koreas-online-security-dead-end/ (확인 — 개발자도구를 막는 프로그램 언급) · 블로그 사례(감)

**가7 ⚠️ 간편인증은 「폰 승인 + PC 확인」 두 단계**
- 증상: 「인증 요청」을 누르면 PC가 기다림 상태가 된다. 폰에서 승인해도 PC는 그대로이고, PC에서 「인증 완료」를 눌러야 넘어간다.
- 대처: 「인증 요청」과 「인증 완료」는 둘 다 사용자가 누른다 — 인증을 시작하고 마치는 것도 로그인이다. 에이전트는 이렇게 안내만 한다: 요청은 한 번만 눌러 주세요(폰에 알림이 쌓여요). 누른 뒤 곧바로 폰에서 앱 알림을 승인하고, PC에서 『인증 완료』를 눌러 주세요. 시간이 지나면 처음부터 다시 해야 해요.
- 하면 안 됨: 이름 · 생년월일 · 전화번호 칸을 에이전트가 채우기(개인정보 입력 · 제출).
- 출처: 세무 업체 도움말(감). 제한 시간 공식 값은 확인 못 함.

**가8 ⚠️ 금융인증서는 6자리 숫자 · 생체인증**
- 증상: 금융인증서를 고르면 6자리 숫자나 생체인증을 묻는다(문서). 별도 창으로 뜨고 처음 쓰는 PC면 문자 · ARS 인증을 더 요구한다는 말도 있다(감 — 출처에 없음).
- 대처: 창이 떴다고만 알리고 사용자에게 맡긴다.
- 출처: https://www.samsungsvc.co.kr/solution/4576800 (문서 — 2026-01-19)

**가9 ⚠️ 간편인증 수단이 갑자기 꺼짐**

## 나. 화면 기술 · 뷰어 · 파일

**나1 ❗ 「도구가 글자 없다」 ≠ 「글자 없다」**
- `get_page_text`는 iframe 안까지 내려가지 않는다. 예: korea.kr 문서 「바로보기」(`docViewer.do`)는 바깥 글자 2자로 「No text content」가 나오지만, 같은 출처 `iframe#innerWrap` 안에 글자 1,632자가 있었다(확인 — 2026-11 직접 봄).
- 대처: SKILL.md 1절 진단 JS로 `iframe,frame`을 거듭 내려가 `contentDocument.body.innerText`를 읽는다.

**나2 ❗ 크롬 내장 PDF 뷰어는 확장 도구가 다 막힌다**
- 증상: `get_page_text`가 「No text content found」, JS가 「Cannot access a chrome-extension:// URL of different extension」.
- 대처: 로그인이 필요 없는 공개 PDF면 WebFetch로 그 주소를 연다. 저장된 파일을 Read 도구로 열면 글자와 페이지 그림이 나온다(확인 — 시험 PDF). 로그인이 필요한 PDF면 스크린샷 · zoom으로 읽거나 사용자에게 묻는다.
- 주의: WebFetch로 파일을 받는 것도 내려받기에 가깝다. 받기 전에 파일 이름 · 크기를 사용자에게 말하고 허락받는다(SKILL.md 2절 「첨부 단추 · 내려받기」).

**나3 ⚠️ 열자마자 JS를 돌리면 「다른 도메인으로 넘어감」 실패**
- 증상: 「Security check failed: the page navigated to a different domain during JavaScript execution」. `.do` 첫 화면이 다른 주소로 다시 보내는 경우가 많다(gov.kr → plus.gov.kr 등 · 확인).
- 대처: 열고 → `tabs_context_mcp`로 지금 주소를 다시 보고 → 그다음 JS. 넘어간 주소가 그 뒤의 기준이다.

**나4 ⚠️ 새로 만든 사이트(SPA)는 처음에 글자가 적다**
- 정부24(plus.gov.kr) · 감사원은 Nuxt였다(확인). 처음엔 틀만 있고 조금 뒤에 채워진다.
- 대처: 2~3초 기다린 뒤 다시 읽는다.

**나5 ⚠️ WebSquare(인스웨이브)**
- 알아보는 표지(확인 — 홈택스 첫 화면): 주소에 `websquare/websquare.html?w2xPath=` · 전역 `WebSquare` · `$p` · `scwin` · class `w2group` · `w2textbox` · id가 `…wq_uuid_277` 같은 자동 번호(다시 열면 바뀔 수 있다 — ref · id를 저장해 두고 다시 쓰지 않는다) · role 속성이 적어 접근성 트리가 얇다.
- 그리드는 보이는 행만 그릴 수 있어서, DOM의 행 수가 전체가 아닐 수 있다.
- 대처: 화면에 보이는 것만 읽는다. 더 있으면 화면의 페이지 단추 · 스크롤로 넘기며 읽고, 다 못 읽었으면 「보인 n행만 읽었다」고 보고한다.
- 하면 안 됨: 화면 뒤에 받아 둔 데이터나 조회 함수를 스크립트로 직접 꺼내기 — 화면에 안 보이는 칸(개인정보 · 내부 값)이 딸려 나올 수 있다.

**나6 ⚠️ 넥사크로(투비소프트)**
- 알아보는 표지(확인 — 넥사크로 14 버전 공개 사이트): `nexacro.Version` · id `mainframe_childframe_form_<부품>` · div로 그려 `innerText`는 읽힌다 · role · aria가 0개라 `find` · `read_page` · `form_input`이 거의 안 듣는다.
- 그리드는 데이터를 화면 단위로 나눠 받기도 한다. DOM에 보이는 행이 전부가 아닐 수 있다.
- 대처 · 하면 안 됨: 나5와 같다(화면에 보이는 것만 · 화면 뒤 데이터나 조회 함수를 직접 꺼내지 않기).

**나7 ⚠️ `javascript:fn_xxx()` 링크와 숨은 폼(전자정부 프레임워크 방식)**
- 본 것(확인): data.go.kr `onclick="javascript:fn_movePage(…)"`와 숨은 칸이 많은 GET 폼(currentPage · perPage …) · seoul.go.kr 목록 `javascript:fnTbbsView('번호')` — `String(fnTbbsView)`로 원문을 읽으니 GET 주소를 만드는 함수였다.
- 대처: ① 함수 원문을 `String(fn)`으로 읽어 GET 주소면 바로 연다 ② GET 폼이면 숨은 칸 이름으로 주소를 만들어 페이지를 넘긴다 ③ POST만 받는 곳이면 페이지 단추를 `find` ref로 한 번 누른다.
- 하면 안 됨: POST 요청을 직접 만들어 보내기. 함수에 엉뚱한 값을 넣어 부르기(알림창으로 멈춘다).

**나8 ℹ️ 단추에 onclick이 없고 주소가 `data-*` 속성에 있음**
- seoul.go.kr 「바로보기」 단추는 `data-url` · `data-name`에 주소와 파일 이름을 담고, 이벤트는 document에 위임돼 있었다(확인).
- 대처: 핸들러를 쫓기 전에 `el.dataset`과 속성 목록부터 본다.

**나9 ⚠️ 도구가 가린 글 `[BLOCKED: …]` · `REDACTED`**
- 증상: JS · 이동 결과에서 주소 뒤 질의 문자열이나 base64처럼 생긴 문자열 자리가 `[BLOCKED: Cookie/query string data]` · `[BLOCKED: Base64 encoded data]` · `REDACTED`로 바뀐다(확인). 페이지가 막은 게 아니라 쿠키 · 토큰이 새지 않게 도구가 가린 것이다.
- 대처: 가려진 것을 「페이지에 없음」으로 읽지 않는다. 주소를 찾는 데 필요하면 `location.pathname`과 인자 **이름**만 본다. 다음 페이지 주소가 가려졌으면 페이지의 「다음」 단추를 `find` ref로 눌러 넘긴다.
- 하면 안 됨: 가린 값을 어떤 방법으로든 돌려받으려 하기 — 안전장치를 우회하는 일이다. 가려진 값을 짐작으로 지어 넣기(세션 토큰일 수 있다).

**나10 ❗ 내가 만든 탭에도 사용자 로그인이 묻어 있다**
- 새로 연 탭인데 seoul.go.kr 상단에 「로그아웃」이 보였다(확인). 같은 크롬 프로필이라 사용자 쿠키를 같이 쓴다.
- 대처: 「로그아웃 · 마이페이지」가 보이면 사용자 이름으로 움직이는 것으로 본다. 신청 · 저장 · 댓글 단추는 근처에도 가지 않고, 사용자 정보가 보이는 화면은 읽지 않는다.

**나11 ⚠️ 내려받기 주소 형식과 한글 파일 이름**
- 형식(확인): `/common/download.do?fileId=…` · `/comm/getFile?…&fileNo=1` · `/down/…`.
- 옛 서버는 파일 이름을 EUC-KR 바이트로 보내 깨질 수 있다(감). 파일 이름은 헤더 말고 링크 글자나 `data-name`에서 가져온다.
- 하면 안 됨: 주소의 번호를 바꿔 가며 더 받기. 횟수 제한이나 일부러 막은 내려받기를 우회하기.

**나12 ⚠️ HWP · HWPX 도구**
- HWPX는 zip이다: 본문 `Contents/section0.xml`… · 순서 `Contents/content.hpf` · 그림 `BinData/`(감 — 형식 공개 문서로는 대조하지 않음).
- HWP(옛 형식)는 OLE 복합 문서라 olefile로 연다. 2026-11에 PDF 글자가 깨진 공고에서 같은 이름 HWP를 olefile로 열어 본문을 다 읽었다(확인 — 직접 해 봄). 본문(`BodyText/Section*`) 흐름은 압축돼 있어 풀고 레코드를 읽어야 하고, 미리보기 글자(`PrvText`) 흐름은 앞부분만 담는다(감).
- pyhwp `hwp5txt`는 오래 갱신되지 않은 베타로 알려져 있고, HWPX를 못 읽으며 표 구조가 빠진다(감). LibreOffice 기본 필터는 옛 HWP만 읽고, 지금 HWP · HWPX는 LibreOffice 확장 기능 H2Orestart가 필요하다(확인).
- 대처: ① 사이트의 「바로보기」나 PDF판부터 ② HWPX면 새 빈 폴더에 풀어 XML 글자만 읽는다 ③ 새 도구 설치는 사용자가 허락한 뒤에만.
- 하면 안 됨: 「배포용」 HWP(암호 · 편집 막힘)를 풀기.
- 출처: https://extensions.libreoffice.org/en/extensions/show/27504 · https://docs.libreoffice.org/hwpfilter.html

**나13 ⚠️ 알림창 · 확인창**
- 페이지가 띄운 alert · confirm은 닫힐 때까지 그 탭의 JS를 멈춘다. 크롬 확장이 이 창을 잘 처리하지 못한다는 사용자 제보가 있다(감).
- 대처: 알림이 뜰 만한 단추(삭제 · 제출 · 확인)는 애초에 누르지 않는다. 떴으면 문구를 그대로 읽어 사용자에게 전하고, 어느 쪽을 누를지는 사용자가 정한다.
- 하면 안 됨: 알림 · 확인창을 페이지 스크립트로 바꿔 끼워 안 뜨게 하거나 저절로 넘어가게 하기 — 사이트 경고를 사람이 못 보게 된다.

**나14 ℹ️ 오른쪽 클릭 · 글자 선택 막기**
- 마우스 동작만 막는다. `innerText`는 그대로 읽힌다(감 — 원리). 막기 스크립트를 지울 필요가 없다. 다만 보기 전용으로 일부러 막은 문서를 통째로 퍼 가지는 않는다.

**나15 ℹ️ 보고서 뷰어(OZ · ClipReport · RexPert · UBI · Crownix 등)**
- 공개 실물은 못 봤다. canvas에 그리는 뷰어면 글자층이 없다(감).
- 대처: 진단에서 canvas · svg 수를 센다. canvas면 스크린샷 · zoom으로 필요한 페이지만 읽는다. 뷰어의 「PDF 저장」은 내려받기라 먼저 묻는다.

**나16 ℹ️ EUC-KR 페이지 · 한글 검색어**
- 이번에 본 7곳은 모두 UTF-8이었다(확인). 옛 사이트면 `document.characterSet`을 본다. EUC-KR이면 WebFetch 글자가 깨질 수 있으니 크롬 화면 글자로 읽는다. 검색어는 주소를 손으로 만들지 말고 검색칸에 넣어 사이트가 스스로 인코딩하게 한다(감).

**나17 ℹ️ 날짜 · 마스크 · 한글 입력칸**
- 프레임워크 달력 · 콤보는 진짜 input이 아니라, `form_input`으로 넣어도 안쪽 값이 안 바뀔 수 있다. 한글 입력 이벤트(IME · keyup)에 기대는 검색칸도 같은 일이 날 수 있다(감). 칸을 눌러 화면 순서대로 넣고, 결과 건수로 조건이 먹었는지 확인한다.

**나18 ⚠️ POST로 넘어간 목록에서 뒤로 가기**
- 증상: 뒤로 가기 · 새로고침을 하면 「양식 다시 제출」 창이 뜨거나 「잘못된 접근 · 세션 만료」로 튕긴다(감).
- 대처: 뒤로 가지 말고 처음 주소부터 다시 연다. 「다시 제출」 창이 뜨면 취소 쪽을 고르고 사용자에게 알린다.

**나19 ⚠️ 문서보안(DRM)이 걸린 첨부**
- 받은 HWP · XLS · PDF가 사내 문서보안으로 잠겨 안 열리는 경우가 있다(감).
- 대처: 풀지 않는다. 「문서보안이 걸려 있음」으로 사용자에게 알린다.

**나20 ℹ️ 확장자는 엑셀인데 속은 다른 파일**
- 공공 사이트가 내려 주는 xls가 사실은 HTML 표이거나 CP949 CSV인 경우가 있다(감).
- 대처: 열기 전에 파일 머리 몇 바이트를 본다(`<` 로 시작하면 HTML, 쉼표 · 따옴표가 보이면 CSV). CSV면 인코딩을 CP949로도 시도한다.

**나21 ⚠️ 고른 값을 원래 화면에 돌려주는 검색 팝업**
- 증상: 검색 조건 칸 옆의 「찾기」 단추를 누르면 새 창이 뜨고, 거기서 고른 항목이 원래 화면의 칸에 채워진다(분류 · 기관 고르기). 새 창은 확장의 탭 묶음 밖이라 탭 목록에 나오지 않는다(확인).
- 까닭: 팝업은 자기를 연 창(`opener`)의 칸을 채운다. 팝업 주소를 같은 탭에서 따로 열면 `opener`가 없고, 원래 화면도 넘어가 버린다.
- 대처(팝업이 같은 출처이고, 로그인 없는 공개 화면에서 검색 조건을 고를 때만):
  1. 누르기 **전에** `window.open`을 감싼다 — `const o = window.open; window.open = function(){ return (window.__h = o.apply(this, arguments)); }`. 단추가 iframe 안에 있으면 그 iframe의 `contentWindow.open`을 감싼다.
  2. 단추는 `find` ref나 좌표 클릭으로 누른다. JS `el.click()`으로 누르면 크롬 팝업 차단에 걸려 `open`이 `null`을 돌려줬다(확인). iframe 안 단추는 `find`에 잡히지 않아 좌표로 눌렀다(확인).
  3. 열자마자의 핸들은 빈 문서(`about:blank`)다(확인). 핸들의 `location.pathname`이 팝업 주소로 바뀌고 `document.readyState`가 `complete`가 된 뒤에 읽는다.
  4. 핸들의 `document`에서 검색칸을 채우고, 「조회」와 결과 줄을 누른다. 값만 넣어서는 안 먹는 칸도 있다(나17).
  5. 원래 화면의 칸이 채워졌는지 다시 읽는다. 팝업이 스스로 닫히지 않았으면 핸들의 `close()`로 닫는다 — 탭 묶음 밖 창이 쌓이지 않게.
- 하면 안 됨: 로그인된 탭 · 넘겨받은 탭에서 쓰기(SKILL.md 0절 ❗ — 거기서는 사용자가 직접 고른다). 사용자 이름으로 내보낼 신청서 · 입력 폼을 채우는 데 쓰기(SKILL.md 4절). 다른 출처 팝업에 쓰기 — 핸들의 `document`를 읽지 못할 것으로 보인다(감 — 시험 안 함) · 그때는 사용자가 직접 고른다. 팝업 안에서 알림창이 뜨면 나13을 따른다.
- 확인한 범위: 2026-11에 직접 만든 시험 페이지(같은 출처 팝업 · 본문에 단추가 있는 판과 iframe 안에 있는 판)에서 Claude in Chrome으로 위 순서를 돌려 원래 화면 칸이 채워졌다(확인). 실제 기관의 공개 화면에서는 시험하지 않았다.

**나22 ℹ️ 글자층이 있는데 글자가 깨져 나오는 PDF**
- 증상: 기관 자료실 PDF에서 글자를 뽑으면 뜻 없는 기호만 나온다. 페이지 안에서 pdf.js로 뽑은 글자층도, 사이트 문서 뷰어가 주는 글자층도 똑같았다(확인 — 2026-11 한 기관 자료실 PDF). 글자층이 없는 것이 아니라 글꼴의 글자 부호가 깨진 것으로 보인다(감 — 글꼴은 뜯어보지 않음).
- 대처: 뽑는 도구를 한 번 바꿔 본다(SKILL.md 2-2절). 그래도 같으면 같은 이름의 HWP · HWPX가 함께 올라와 있는지 본다. 없으면 페이지 그림으로 읽는다 — 로그인 없는 공개 PDF면 나2의 길로, 아니면 사이트의 「미리보기」 뷰어에서 페이지 번호 칸으로 넘기며 필요한 페이지만 zoom으로. 「글자가 깨져 그림으로 읽었다」고 보고에 적는다.
- 하면 안 됨: 깨진 글자를 짐작으로 풀어 옮기기.

- 몇 분 뒤 연장 단추나 남은 시간 표시가 나오고, 안 누르면 입력하던 것이 날아간다. 개인정보 안전성 확보조치 기준이 자동 로그아웃을 요구한다고 알려져 있다(감 — 고시 원문 대조 안 함). 몇 분인지는 사이트마다 다르다.
- 대처: 로그인된 탭에서 긴 일을 하면 처음 진단에서 남은 시간 표시를 찾아 알린다. 긴 읽기는 공개 화면이나 API로 한다.
- 하면 안 됨: 연장 단추를 에이전트가 되풀이해 눌러 세션 붙잡기(사람에게 묻는다).

**다4 ⚠️ 비밀번호 몇 번 틀리면 잠금**
- 같은 기준이 일정 횟수 인증 실패 때 접근을 막도록 한다(감 — 2차 요약). 로그인 실패 화면을 보면 다시 시도하지 말고 사용자에게 넘긴다.

**다5 ⚠️ 정기점검 · 서비스 중단(정부24)**
- 정부24는 점검을 건마다 공지한다. 예: 2026-09-11 19:30 ~ 09-12 19:00(23시간 30분). 공지에 「증명서 발급 대체 사이트 안내」가 있다 — 납세증명은 홈택스, 건축물대장은 세움터, 지방세 증명은 위택스, 토지대장 같은 부동산 정보는 일사편리에서 확인하라는 식이다(확인 — https://www.gov.kr/portal/ntcItm/128054?Mcode=11226).
- 대처: 막히면 먼저 공지 게시판을 본다. 장애로 짐작해 되풀이하지 않고, 공지에 적힌 대체 사이트를 사용자에게 알린다.

**다6 ⚠️ 운영 시간이 정해진 화면 · 기능**
- 홈택스 신고 화면은 마감철에 밤에 닫힌다(예: 06:00~24:00 — 감, 국세청 보도자료 검색 요약). 인터넷등기소 상호검색처럼 기능별로 운영 시간이 다른 곳도 있다(문서 — 등기예규 게재 사이트).
- 대처: 시간 밖이면 「운영 시간 밖」으로 보고하고 끝낸다. 「막혔다 · 차단됐다」로 단정하지 않는다.

**다7 ⚠️ 장애 때 읽은 값은 흔들린다**
- 사이트 장애가 나면 기관이 마감을 미루거나 일정을 바꿔 공지하는 일이 있다(감).
- 대처: 장애 중에 읽은 날짜 · 값은 복구 뒤 그 사이트의 공지와 다시 대조한다.

**다8 ⚠️ 웹방화벽 거절 화면**
- 증상: 「The requested URL was rejected. Please consult with your administrator. Your support ID is …」 · 403 · 「비정상적인 접근」.
- 대처: 문구 · support ID · 시각을 그대로 적어 사용자에게 넘긴다. 같은 요청을 되풀이하지 않고, 공식 API나 사람이 직접 여는 방법으로 바꾼다.
- 하면 안 됨: 헤더 · 사용자 에이전트를 바꿔 다시 보내기 · 프록시 · VPN.
- 출처: F5 커뮤니티 글(감 — 한국 기관 실사례는 확인 못 함)

**다9 ⚠️ 접속 대기열(넷퍼넬 등)**
- 대기 순번은 쿠키에 담긴다. 「순번 유지」 기능은 기본이 꺼짐이고, 꺼져 있으면 재요청이 1초만 멈춰도 순번이 사라진다. 켜면 기본 60초 · 최대 2시간 보존된다. 시크릿 창 · 쿠키 지우기 · 다른 브라우저는 순번을 잃는다. 새로고침이 어떻게 되는지는 문서에 없다(확인 — 제조사 문서 https://docs.stclab.com/products/netfunnel/user-guide/segment/basic-control-segment/advanced-queue-position-retention).
- 대처: 대기 화면이면 그 탭을 그대로 둔다. 이동 · 새로고침 · 탭 닫기를 하지 않고, 같은 사이트를 다른 탭으로 따로 열지 않는다. 기다리는 동안 사용자에게 알린다.
- 하면 안 됨: 대기열 우회 스크립트.

**다10 ⚠️ 막힌 까닭이 사이트인지 도구인지 오류 문구로 가른다**
- `unable to fetch from …` · `Unable to verify if domain is safe to fetch` = 도구 쪽 도메인 검사(감 — 이슈 모음) · `getaddrinfo ENOTFOUND` = DNS 실패(주소부터 다시 본다) · 웹방화벽 문구 · 403 = 사이트 쪽.
- 2026-11 조사에서 WebFetch로 gov.kr · hometax · law.go.kr · data.go.kr · korea.kr · kosis · opendart가 다 열렸다(확인 — Windows PC의 Claude Code 데스크톱 앱). 그러니 「WebFetch는 해외 IP라 공공 사이트가 막는다」는 이 환경에선 맞지 않았다. 클라우드 세션에선 다를 수 있다.

## 라. 왜 몰아서 긁지 않나 (요약일 뿐 법률 자문이 아니다 — 판단이 필요하면 원문과 전문가에게)

- **보호조치 · 약관을 넘어 들어가면 정보통신망법 문제가 될 수 있다.** 정보통신망법 제48조 제1항은 정당한 접근권한 없이, 또는 허용된 접근권한을 넘어 정보통신망에 침입하는 것을 금지한다(문서 — 2024-01-23 개정 판 문언을 그 조항을 인용한 다른 판결의 요지로 대조 · 현행 판 원문은 대조 못 함 · 조문을 인용할 땐 law.go.kr 원문으로 다시 대조한 뒤에). 대법원 2021도1533(2022-05-12, 숙박 앱 크롤링 사건)은 접근권한을 정하는 쪽을 서비스제공자로 보고, 제한됐는지는 보호조치 · 약관 같은 객관적 사정으로 판단한다는 법리를 밝혔다. **다만 그 사건 자체는 무죄로 끝났다** — 약관이 「이용」을 제한한 것이지 「접근」을 제한한 것이 아니라고 보았고, 정보통신망법 · 저작권법 · 업무방해 모두 무죄, 검사 상고 기각이었다(문서 — https://www.nepla.ai/case/대법원/2021도1533). 이 스킬이 로그인 화면 · 차단 화면 · 「자동 수집 금지」 약관을 만나면 멈추게 하는 것은 이 판결의 결론이 아니라, 위험을 피하려는 보수적인 선택이다.
- **한 사이트를 되풀이해 통째로 모으면 데이터베이스권 문제가 될 수 있다.** 위 판결은 데이터베이스 제작자의 권리가 침해되려면, 조금씩이라도 반복 · 체계적으로 모아 「상당한 부분」을 복제한 것과 같은 결과가 되어야 한다고 좁게 보았다(문서). 채용 사이트 크롤링 사건에서는 원심이 데이터베이스권 침해 · 부정경쟁을 인정했고 대법원(2017다224395)이 확정했다(감 — 보도 https://www.lawtimes.co.kr/news/articleView.html?idxno=121766). 필요한 몇 건만 읽고, 대량이면 공식 API · 제공 파일로 간다. 반복 수집 전에는 robots.txt를 한 번 본다.
- **남의 글을 요약 · 번역해서 다시 낼 땐 공공누리 유형부터 본다.** 1유형 출처표시 · 2유형 + 비상업 · 3유형 + 변경 금지 · 4유형 + 비상업 + 변경 금지. 모든 유형에서 출처표시가 필수이고, 변경 금지에는 번역 · 형식 바꾸기도 들어간다(확인 — https://www.mcst.go.kr/kor/s_open/kogl/koglType.jsp?pTab=02).
- 사용자 본인 자료(세금 · 보험 · 행정)는 에이전트가 사용자 아이디로 대신 긁지 않는다. 공공 마이데이터(정부24 앱)나 기관 API로 받게 한다.
